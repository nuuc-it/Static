What NForms does

NForms shows your form as a web page and saves each answer in a Google Sheet. The questions live in the same spreadsheet, on the Settings, Fields, Options and Conditions tabs. To change a form, edit those tabs; this page does not edit questions.

Two ways to start

From a Google Form: enter a form key and the form's response spreadsheet (or the Google Form). Click Initialize configuration, then Import missing questions, then Register. The Google Form keeps working, and both save to the same sheet until you turn the Google Form off.

Without a Google Form: create a blank Google Sheet, then enter a form key and the sheet's link. Click Initialize configuration. Edit the example question in the Fields tab and add your own. Click Initialize configuration again to add answer columns for new questions, then Register. A new form starts Off; set formEnabled to TRUE in Settings when it is ready.

The fields

Form key is the short name that identifies this form, for example activity. It appears in the form's web address. Use 2 to 63 lowercase letters, digits or dashes, starting with a letter. Each form needs its own key, and a spreadsheet can be registered under one key only.

Spreadsheet URL or ID is the Google Sheet that holds the answers and the questions. Paste its address or just its ID. Required unless you enter a Google Form that already has a response sheet.

Google Form URL or ID is optional. Enter it only when you are starting from an existing Google Form. Leave it empty to start without one. If the sheet is already linked to a Google Form, NForms detects it.

Buttons

Inspect checks the spreadsheet and tells you the next step. It changes nothing.

Initialize configuration adds missing tabs, settings and answer columns. It never changes what is already there. Safe to repeat.

Import missing questions copies questions from the Google Form that are not in Fields yet. It never changes questions you edited. On a registered form, new questions arrive switched off.

Register checks the configuration and, if it is valid, adds the form to the list. It changes nothing in the spreadsheet.

The form list

Form is the form's key and title. Responses is how many answers are saved. Last submission is when the latest answer arrived. Status says whether the form is on and what to do next, with up to three problems listed.

Links

Submit is the public form people fill in; anyone with the link can use it.

Auditor is where signed-in reviewers search and correct answers.

Sheet opens the spreadsheet with the answers and the questions. You need your own access to it.

Google Form opens the original Google Form while it is still linked.

Configuring questions

A form without a Google Form starts with a worked example in the Fields, Options and Conditions tabs. Every example Field ID begins with example_. Edit them to suit, or hide them (see Hide or delete), and add your own rows. Questions appear in Order, within their section.

Fields tab: one row per question or page break

  • Field ID: the question's permanent key, lowercase letters, digits and underscores. Do not change it once answers exist.
  • Source Item ID: the Google Form item this row came from. Leave blank for questions you add.
  • Order: a number; lower numbers come first.
  • Section ID: the page the question is on. main is the first page. A PAGE_BREAK row starts a new page, and its own Section ID is the name later questions use.
  • Heading: a short name for you; not shown to respondents.
  • Prompt: the question as respondents read it.
  • Help Text: smaller explanatory text under the question.
  • Type: see Question types below.
  • Required: TRUE if an answer must be given.
  • Enabled: TRUE shows the question; FALSE hides it.
  • Response Header: the exact column title in the response tab where the answer is saved. It must match one column. Click Initialize configuration to add a column for each new enabled question.
  • Default Value, Validation JSON, UI JSON: optional advanced settings; leave blank unless you were told what to enter.

Question types (Fields, Type)

  • TEXT: one short line. PARAGRAPH_TEXT: several lines.
  • MULTIPLE_CHOICE: pick one of the options, shown as buttons. LIST: pick one from a drop-down. CHECKBOX: pick any number. Each needs rows in the Options tab.
  • SCALE: pick one number. Proposed: one Options row per step, for example 1 to 5.
  • DATE, TIME, DATETIME, DURATION: a date, a time of day, both, or a length of time.
  • PAGE_BREAK: starts a new page; it is not a question and has no answer column. Import also reads SECTION_HEADER, GRID and CHECKBOX_GRID rows from a Google Form; the example does not include them.

Options tab: one row per choice

  • Field ID: the question the choice belongs to. Order: its position.
  • Value: what is saved in the answer column. Label: what respondents read; usually the same.
  • Enabled: FALSE hides the choice.
  • Navigation: MULTIPLE_CHOICE only; where this choice sends the respondent: CONTINUE, GO_TO_PAGE, RESTART or SUBMIT. Target Section ID: for GO_TO_PAGE, the Section ID of the page to jump to. Leave both blank otherwise.

Conditions tab: one row per rule

Rules change what the form shows depending on an earlier answer. Proposed, enforced from M2: NForms does not apply them yet and does not reject other values yet. The example rules are switched off.

  • Rule ID and Order: the rule's name and its position. Enabled: TRUE turns the rule on.
  • Trigger Field ID: the question whose answer is tested. Comparison Value: the value it is tested against.
  • Operator: equals, not-equals, contains, is-empty or is-not-empty. The last two ignore Comparison Value.
  • Action: show shows the target question when the test is true; hide hides it; skip-to-section jumps to a page.
  • Target Field/Section ID: the Field ID for show and hide, or the Section ID for skip-to-section.

Settings tab: Key and Value

  • schemaVersion: the layout version; do not change. formKey: the form key.
  • title, description: shown at the top of the form. confirmationMessage: shown after submitting.
  • responseSheet: the tab where answers are saved. formEnabled: true opens the form to respondents; false closes it. collectEmail: true asks for an email address.
  • notificationEmails: comma-separated addresses to tell about new answers; blank means none.
  • htmlFormUrl, sourceFormId, sourceUrl, importedAt: records of where the form came from; leave them alone.

Hide or delete

To remove a question or choice from the form, set Enabled to FALSE. Its answers stay in the response tab. Delete a row only for a question you added by mistake and that has no answers; if it came from a Google Form, Import would add it back. Never delete or rename a response column.

Worked example

The seeded form has one question of each type on the first page (example_text to example_scale), then example_followup, then a PAGE_BREAK example_page_end followed by example_last.

  • example_choice has two options. Show more has Navigation CONTINUE. Jump to the last page has Navigation GO_TO_PAGE and Target Section ID example_page_end.
  • example_checkbox, example_list and example_scale have plain options with no Navigation.
  • Rule example_rule_show: when example_choice equals Show more, show example_followup.
  • Rule example_rule_skip: when example_list equals Option B, skip-to-section example_page_end.
  • Both rules are Enabled FALSE until you turn them on. To make the form your own, set Enabled to FALSE on the example rows, add your questions, then click Initialize configuration to add their answer columns.

Good to know

Refresh reloads the form list. Sign out forgets your sign-in on this browser. Details, under the buttons, shows the raw server reply; it is for troubleshooting and never contains answers.

The Status column shows what to do next for each form.

To hide a question, set Enabled to FALSE in Fields. Do not delete the row: Import would add it back.

Nothing on this page deletes answers.
